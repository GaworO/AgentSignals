TANJA · STEP 2 · OPENAI CONTEXT REVIEWS

Connect AI to your Railway service.

Your ES and MNQ alerts already work. This update adds AI interpretation to the same separate tanja service. The API key is stored privately in Railway.

Current mode: observation only. AI answers appear in the dashboard and are saved for comparison with the strategy. There is no broker connection or order-sending function in this build. A passed evidence check is not proof of Tanja 1:1 fidelity.

1. Upload the updated service code

  1. Unzip Tanja_Railway_Step2_AI_20261008.zip. It contains services/tanja/.
  2. In the GitHub repository connected to your existing tanja Railway service, update the files in services/tanja/ with the extracted files. Keep that path exactly; do not create a second nested services/tanja/services/tanja folder. If using GitHub's website, open the repository root and use Add file → Upload files with the extracted services folder.
  3. Commit the update. Let Railway deploy it, or redeploy the latest commit if automatic deployment is off.
  4. Keep the current Railway root directory /services/tanja, existing /data volume, feed token, dashboard password and ticker variables. Keep one replica and the supplied Dockerfile start command.
  5. Open Tanja health. The updated response includes version: "2.0-ai-observe". In the dashboard, AI context now has an AI reviews section. AI is initially disabled. Existing candle counts should remain.

The database update only adds a new review table/index. Keep the existing volume attached. No TradingView alert or Pine change is needed.

2. Create a private OpenAI API key

  1. Sign in to the OpenAI API platform and select or create a project for Tanja.
  2. In API billing, ensure this project can make paid requests. A ChatGPT subscription does not supply this service with an API key or API credit.
  3. Open API keys and create a new secret key for this project. A restricted key must allow writing Responses requests.
  4. Copy the key directly into Railway in the next step. Do not put it in chat, GitHub, Pine, a screenshot or the dashboard.

Use the API project's usage and billing controls as an additional cost check. The service limits calls and output tokens; it does not promise a fixed dollar cap.

4. Understand when the first answer appears

The pilot samples the latest available snapshot between 09:30 and 11:00 New York, weekdays. It sends at most six attempts per New York calendar day, at least 15 minutes apart. These are observation and cost-control settings, not reconstructed trading rules. This does not evaluate every entry opportunity.

A call also requires both feeds to be no more than 120 seconds old, 15 consecutive recent minutes on both markets, and at least three complete 4h candles and three complete 1h candles per market. TradingView alerts only stream forward. Starting the alerts at 04:20 NY cannot supply three 4h candles by today's open. Allow overnight collection; the exact wait depends on candle alignment and market closures. More history, contract alignment and news are still needed for full context.

5. Check the first real review

  1. Open Tanja → AI context → AI reviews.
  2. Confirm a row shows market cutoff, answer-received time, result and token usage. The response becomes available only at the later time; never backdate it to the candle cutoff.
  3. Open the row's JSON audit. It contains the frozen input, model request (without API credentials), provider response, interpretation and evidence checks.
  4. Review its bias, selected setup, cited levels and missing context. Compare with the chart available at that time.
  5. Share the review result/error code here if needed, with no credentials. That lets us distinguish a working connection from a strategy-quality problem.

HTTP_401: key/authentication. HTTP_403: project/model permissions. HTTP_404: model or endpoint availability. HTTP_429: quota, billing or rate limit. RESPONSE_FAILED_EVIDENCE_VALIDATION: answer refused, incomplete or failed local checks; inspect the saved raw response. Network timeout or interruption has an unknown provider outcome and may still have incurred cost. No automatic retries are made.

What is sent and saved?

Only the research prompt, schema and market-only ES/MNQ snapshot are sent to OpenAI. No broker login, Railway feed token, dashboard password or account ID is sent. Requests use store:false; this is not a claim of zero provider retention. Railway's private volume saves each attempted review and its response for audit. Audits use the same dashboard authentication and persist across redeploys. Monitor volume usage as the archive grows.

To stop future AI calls: set TANJA_AI_ENABLED=false on tanja and deploy. Candle collection continues. An already submitted request may still finish and be billed.

After the connection works

Evaluate recorded answers on unseen sessions, review disagreements and unresolved rules, then build and test the separate execution adapter and account-wide risk controls. 50K Builder remains disconnected in this version. Running other strategies on the same account must be included in that later risk design.

Your laptop can be off. TradingView delivers the bars and Railway runs the API worker.
