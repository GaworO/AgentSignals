1. Put the new files in your GitHub repository

  1. Unzip Tanja_Railway_Step1_20261008.zip. The top-level folder is services; inside it is tanja.
  2. Open the GitHub repository used by your Railway project. Upload the entire services/tanja folder, keeping all its subfolders. Use a new branch such as tanja-feed-v1 if you want to avoid triggering existing services while setting up. Set the new Railway service to that same branch.
  3. Verify GitHub shows services/tanja/Dockerfile, app.py, store.py, worker.py, static/, vendor/ and tradingview_feed.pine. Do not upload passwords, tokens, test databases or research CSVs.

This delivery does not replace your current agent.py or dashboard.py. The menu addition is a small separate change in step 6.

2. Add a new service in the existing Railway project

  1. In the project shown in your screenshot, select + New → GitHub Repo and choose that repository. Name the new service tanja.
  2. In its Settings → Source, select your deployment branch. Set Root Directory to /services/tanja.
  3. If using the supplied configuration file, set its path to /services/tanja/railway.json. Railway's config-file path is relative to the repository, not the service root.
  4. Use the included Dockerfile builder. Leave any custom Start Command blank; the Dockerfile supplies it. Set healthcheck path to /health. Run one replica.
  5. Add a new volume to the Tanja service, named tanja-volume, mounted at /data. It must be separate from agentsignals-volume and agent-50k-volume.
  6. Keep the service running continuously; disable serverless/app sleeping for this collector. A webhook arrives every minute per market.

Generate two different values locally with a password manager, or run this command once per value:

python3 -c 'import secrets; print(secrets.token_urlsafe(32))'

Paste them directly into Railway. Do not send them in chat or store them in GitHub. This step needs no OpenAI key, Tradovate API key or TradersPost webhook.

  1. Deploy the service. If it started before the variables were set, redeploy after saving them.
  2. In Settings → Networking, choose Generate Domain. Copy the new Tanja HTTPS address. Railway supplies PORT; use its detected container port when prompted.
  3. Open https://YOUR-TANJA-DOMAIN/health. It should return "ok": true, "mode": "OBSERVE_ONLY".
  4. Open the domain itself. Sign in with username tanja and your TANJA_DASHBOARD_PASSWORD. Both feeds should initially say No data.

4. Install the Pine feed twice

Keep your existing MNQ → AgentSignals alert. These are two additional alerts for the independent Tanja service.

  1. Open TradingView. Use your CME real-time data subscription and standard 1-minute candles.
  2. Select CME_MINI:ES1!. Enable Electronic/Extended Trading Hours (ETH). Do not use Heikin Ashi or other synthetic candles.
  3. Open Pine Editor, create a new indicator, replace its contents with tradingview_feed.pine, save as Tanja closed 1m feed v1, and choose Add to chart. The same code is also available at https://YOUR-TANJA-DOMAIN/pine after signing in.
  4. Create an alert. Condition: Tanja closed 1m feed v1 → Any alert() function call. The script generates its JSON message; do not replace it with buy/sell text.
  5. Set the alert name to Tanja ES 1m. In Notifications enable Webhook URL and enter:
    https://YOUR-TANJA-DOMAIN/feed/YOUR-TANJA-FEED-TOKEN
    This is the Tanja collector URL, not TradersPost. Keep it private.
  6. Use the latest expiration your plan permits, and create the alert. Webhooks require TradingView two-factor authentication.
  7. Repeat on CME_MINI:MNQ1!, still 1m + ETH, using the same indicator and webhook URL. Name this alert Tanja MNQ 1m.

Alerts run from a saved snapshot of the chart and script. After changing the code, symbol, timeframe or session settings, recreate the affected alert. Historical chart candles are not backfilled by alerts.

For CME futures, Pine names the default ETH session regular and RTH us_regular; the receiver accounts for this. The script emits the symbol, exact ticker, UTC opening/closing times, and OHLCV only at a confirmed live candle close. Chart display timezone can be New York for convenience; transmission uses UTC milliseconds.

5. Verify the connection before moving on

  1. While the market is trading, wait for two one-minute bars to close.
  2. In TradingView's alert log, check both alerts fired and inspect Webhook status.
  3. On the Tanja Overview page, both feed counters should increase. Market data should show completed processing jobs.
  4. On AI context, confirm the snapshot cutoff corresponds to the latest shared closed minute. AI status must still be Not connected.
  5. Download ES and MNQ CSVs separately. Check their prices and last timestamps against the two charts.
  6. Redeploy Tanja once and confirm the counts/history survive. This verifies the volume rather than relying on temporary container storage.

One-minute data accumulates immediately. Complete 1h/4h candles require warmup; a few minutes of data cannot reconstruct higher-timeframe context. Missing history, contract adjustments and news remain visible limitations. A missing candidate is not necessarily a failure—there may be no inversion.

6. Add “Tanja” to the existing left menu

Do this against the current source of your main AgentSignals service, not an older cached copy.

  1. Copy services/tanja/integration/tanja_menu.py to the repository root, beside dashboard.py.
  2. In the main agent.py, find dashboard.register(app). Add these lines immediately after it:
    import tanja_menu
tanja_menu.install(dashboard)
  3. On the main AgentSignals Railway service, add TANJA_URL=https://YOUR-TANJA-DOMAIN.
  4. Ensure TANJA_PARENT_ORIGIN on Tanja matches the main dashboard's exact HTTPS origin, then deploy the menu change to the main service.
  5. Open Tanja directly once to sign in. The main sidebar now contains Tanja → Overview / Trade candidates / AI context / 50K Builder executions / Market data. The pages are served by the separate Tanja service.

If your browser blocks authentication inside the embedded panel, use its open ↗ link to open Tanja directly. No password belongs in TANJA_URL.

For a downloaded checkout, an optional guarded installer applies the same two-line change and keeps a backup:

python3 services/tanja/integration/install_menu.py --repo /path/to/current/checkout

It refuses iCloud placeholders or an unfamiliar registration line. The main files in the workspace were placeholders, so the live menu has not been edited or deployed by this delivery.

Troubleshooting

What you seeWhat to check
Deployment fails immediatelyRequired variables, Dockerfile/root directory, and a writable /data volume.
404 in webhook logTanja domain, /feed/ path and exact feed token.
422 in webhook log1m, standard candles, ETH, configured exact ticker, live data; delayed bars older than 180 seconds are rejected. Check the dashboard diagnostics.
409 in webhook logA different candle arrived for an existing symbol/minute. Check duplicate alerts, feeds and contract settings. Original data is retained.
One market stays at zeroBoth alerts exist, have not expired, and point to the new Tanja URL.
Stale / closedExchange closure or feed interruption. This version has no holiday-calendar inference.
